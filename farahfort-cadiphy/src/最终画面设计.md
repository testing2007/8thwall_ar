可以做，而且这张 CADIPHY 酒标比 Oreo 包装更适合做“酒庄酿造过程”主题。整体保留 Oreo 视频的节奏，但不照搬饼干堆叠，改成：

**飞鸟徽章通电 → 能量流向 CADIPHY → 酒标上抽 → 内部酒窖显现 → 葡萄落入红酒 → 参数板逐项打印。**

## 一、最终画面设计

### 1. 飞鸟徽章启动

酒标顶部中央木桶上的飞鸟作为启动核心：

- 飞鸟轮廓先从暗红变成金红色自发光。
- 从鸟头或双翼中心向外描边。
- 三只木桶边缘随后依次亮起。
- 周围出现少量金红色火花和能量颗粒。
- 光线不要照亮整个平面，只描飞鸟和木桶轮廓，质感会更高级。

建议颜色：

```text
核心亮色：#FFD38A  暖金
能量主色：#FF4B28  橙红
暗部余光：#6E0D10  酒红
```

### 2. 光线移动到 CADIPHY Logo

能量从中央木桶两侧向下流动：

```text
飞鸟
 ↓
左右两条弧形能量线
 ↓
两侧圆形印章
 ↓
CADIPHY 字母
```

到达 CADIPHY 后，不要让整个单词同时出现，而是从中央向左右点亮：

```text
P/H 附近先亮
→ 向 CADI 扩散
→ 向 PHY 扩散
```

最后 Logo 轻微向观察者方向突出一次：

```text
Scale：1.00 → 1.08 → 1.00
Y：0 → -0.003m → 0
```

仍沿用你的坐标约定：

```text
X：左右
Z：上下
-Y：离开瓶身、朝观察者
+Y：进入瓶身
```

## 二、酒标抽出方式

建议将**飞鸟木桶和 CADIPHY 保持在原位置**，只抽出酒标中下部的主体区域，大约从绿色横线下面开始，包括：

- RISERVA
- 50
- 年份、酒精度和容量
- 底部产区文字

如果整张酒标全部抽走，瓶子正面会突然失去识别主体，视觉也容易显得空。分成“顶部徽章固定、主体标签上抽”更合理。

抽出动作：

```text
F50：保持原位
F55：开始松动，向观察者移动约 2mm
F60：向上移动
F78：主体酒标移动到顶部徽章上方
F84：轻微回弹后停住
```

动画属性只使用：

```text
location.y：0 → -0.002
location.z：0 → 酒标主体高度的 0.85～1.0 倍
```

不要改变 X，也不需要旋转。

### 必须处理的视觉问题

真实瓶子上的酒标不会真的消失，所以在虚拟酒标抽走后，需要用一个“酒红色内部窗口”覆盖原来的实体酒标：

```text
Portal_Mask
├── 深酒红色背景
├── 金色发光边框
├── 半透明酒槽
└── 葡萄与酒液
```

这个窗口可以理解成一个 AR 传送门。它负责遮住真实酒标，同时展示瓶子内部动画。

## 三、内部“葡萄掉进葡萄酒”

这里不建议模拟真实液体，流体模拟体积大、GLB 也不能直接保存模拟效果。使用轻量化的视觉假象即可。

### 内部结构

```text
Wine_Chamber
├── Chamber_Back         深红背景
├── Wine_Surface         酒面椭圆
├── Wine_Glass_Front     暗红透明前层
├── Grape_Rig_01～12     葡萄
├── Splash_01～03        溅起的酒滴
└── Wine_Ripple_01～03   酒面波纹
```

### 葡萄下落动画

建议准备 9～12 颗葡萄，不要整串一起落：

```text
第一批：3颗
第二批：4颗
第三批：3～5颗
```

每颗葡萄错开 2～3 帧：

```python
start_frame = 80 + index * 3
end_frame = start_frame + 12
```

运动过程：

```text
起点：窗口顶部附近
终点：酒面以下一点
Z：从高到低
X：左右随机少量偏移
Rotation：下落过程中轻微滚动
Scale：1.0 → 0.92
```

葡萄接触酒面的瞬间：

- 葡萄短暂压缩：`Scale Z = 0.8`
- 酒面产生一个金红色圆环。
- 两三滴酒液向两侧弹起。
- 葡萄继续沉入酒液，逐渐被深红色前层遮住。

这样不依赖透明度动画，也能表现“沉入红酒”。

### 最终内部画面

葡萄全部落下后：

- 下方形成半透明深红色酒液。
- 酒面缓慢波动。
- 2～3 颗葡萄隐约停留在酒液内部。
- 背景可加入非常淡的橡木桶线稿，呼应顶部徽章。

## 四、透明参数信息板

参数板建议出现在瓶子右侧，略微朝向摄像机：

```text
位置：瓶子右侧约 70～90mm
高度：与酒标中部平齐
尺寸：宽约 65mm，高约 105mm
颜色：暗红透明底 + 金色细边
```

板上的内容先采用照片中能够确认的信息：

```text
CADIPHY RISERVA

Vintage             2019
Alcohol             15.5% vol
Capacity            750 ml
Origin              Italy
Category            Red Wine
```

其中 `Category` 和更详细的产区信息，最好以后根据酒标高清平面图核对。

打印方式参考 Oreo：

1. 信息板边框从下向上构建。
2. 标题 `CADIPHY RISERVA` 从左向右出现。
3. 参数逐行打印。
4. 每一行都是“图标先出现 → 横线展开 → 数值出现”。
5. 当前正在打印的一行带一条细小扫描线。

GLB 不适合做材质透明度逐字动画，最稳定的实现是：

- 每行文字单独做成 PNG 平面。
- 每行外套一个 Rig。
- 通过 `Scale X：0.001 → 1.0` 实现从左向右展开。
- 各行错开 5～6 帧。

## 七、哪些内容放 Blender，哪些放 8th Wall

尽量让 Blender 承担主要动画：

| 内容                   | 实现位置                 |
| ---------------------- | ------------------------ |
| 飞鸟与木桶描边         | Blender 网格动画         |
| 光线向下移动           | Blender 分段网格错峰动画 |
| 酒标上抽               | Blender                  |
| 葡萄下落与旋转         | Blender                  |
| 波纹、酒滴             | Blender                  |
| 信息板展开和逐行打印   | Blender                  |
| 播放/重新播放动画      | 8th Wall                 |
| Bloom 发光增强         | 8th Wall/Three.js        |
| 识别丢失后的暂停与恢复 | 8th Wall                 |

发光材质可以导进 GLB，但 Blender 中的 Bloom 不会随 GLB 一起导出。因此模型里负责“颜色变亮”，8th Wall 再加一层 Bloom 才能看到真正的光晕。
